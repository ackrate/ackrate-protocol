# AP2 v0.2 helpers

Import the v0.2 helpers through the explicit package entry point:

```ts
import {
  AP2_OPEN_PAYMENT_VCT,
  signAp2Mandate,
  createAp2ComplianceValidator,
  InMemoryAp2ReplayStore,
} from "@ackrate/ap2/v02";
```

The default `@ackrate/ap2` entry point retains its v0.1 API and signatures.
The v0.2 entry point delegates its v0.1 compatibility functions to that implementation.
Both entry points share the current SD-JWT verifier and replay store.

## Payment admission

The OpenPayment profile requires one merchant, an exact budget, on-demand execution,
an expiry, an agent key, and a checkout reference. Unsupported constraints fail validation.
The validator checks the user's signature, merchant, amount, expiry, and checkout reference.
Admission consumes replay state atomically. Use a durable replay store in a deployed service.

The merchant helpers verify open and closed authorization chains against the expected
merchant and checkout. The pool helpers bind the historical registry, schedule,
participant, and time window.

## Contract compatibility

The authorization encoders target the historical contract extension interface.
Their signed wire identifiers remain unchanged to preserve existing signatures.
These helpers do not add those methods to the current Mainnet V2 contract.
They do not prove that a deployment accepts an encoded authorization.

Check the target contract's interface before submitting an authorization.
The contract enforces payment limits. These library functions validate admission
and encode data for a compatible contract.
