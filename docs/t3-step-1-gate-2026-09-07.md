2-of-3 account; it does **not** use the older contract's OpenZeppelin role system.
The original grant wording naming OpenZeppelin must be reconciled explicitly
with that implementation, not reported as unchanged.

The project owner explicitly deferred integrated timelock protection from
Step 1. Current upgrades require administrator authorization and paused state,
but no enforced delay. The separate implementation remains in the
[contract repository](https://github.com/ackrate/ackrate-protocol-contracts/tree/main/contracts/mainnet);
future integration requires its own design, verification, and authorization.
Deferral is project direction, not evidence of Foundation acceptance.

The private V2 playbook names keyholder roles and explains lost-key recovery.
A completed, dated independent-custody confirmation was not located; neither
on-chain thresholds nor ephemeral signature tests prove that operational fact.

For TypeScript consumers, install the normal Node development toolchain
(`typescript` and `@types/node`) in the consuming project. The independent
check initially omitted Node's global types; adding those developer types
resolved the missing `Buffer`/`NodeJS` declarations without weakening strict
checking or adding unrelated runtime packages.

**Technical deployment and release gates pass.** Step 1 awaits the project
owner's acceptance of the documented native-authorization wording in place of
the original OpenZeppelin wording. Do not present that scope change as already
accepted by the Foundation. The user reviews Step 1 before any work resumes on
Step 2.
